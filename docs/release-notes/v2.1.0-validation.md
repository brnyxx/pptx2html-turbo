## PowerPoint-Native Exactness Boundary

The required PowerPoint-native text-layout set is incomplete. Eleven native reference decks are
absent, so the text-layout family is not eligible for exact promotion. This remains an expected
non-blocker for the approximate/high-fidelity v2.1.0 release.

The approved general claim remains:

`96% under the documented general conversion evaluation contract`

It is permitted only for a complete passing signed portable profile wave. It is not a Microsoft
Office fidelity claim and does not promote any PPTX capability to `exact`.

## CI Runtime Review

The full evaluation discovery currently runs independently in `ci.yml`, `release.yml`, and
`publish-npm.yml`. `evaluate/check_exactness_contract.py` also requires each publication workflow
to contain that discovery gate before publishing. The npm receipt shows that validation consumed
31 minutes 22 seconds while the actual dual publish consumed 11 seconds.

This is safe but operationally redundant. A future change should run evaluation once for an exact
commit SHA, publish a tamper-evident SHA-bound validation receipt, and make GitHub Release and npm
publication verify that receipt before running only their package-specific smoke tests. The gate
must not be removed until that replacement and its fail-closed contract tests exist.
